## 3. jack (j15): my brief's mechanism was wrong, and its Target B was false

**Target A is true for all `k` — and vacuous.** With `v 0 = P₀ = 0`, `oddCircleEq` loses **all three** `z`-terms,
not just the quadratic one: the linear coefficients are `conj (v 0) · v ⟨m+1⟩` and `v 0 · conj (v ⟨m+1⟩)`, both
carrying `v 0`. What remains is the constant `‖v ⟨m+1⟩‖² − ‖v last‖²`, and the odd Plücker relation
(`plucker_odd` + `conj_subVec_Q0` + `conj_crossVec_odd_last`) forces it to `0`. Hence

```lean
oddCircleEq_of_P0_zero : v 0 = 0 → oddCircleEq m v z = v⟨m+1⟩*conj v⟨m+1⟩ − v_last*conj v_last
kernel_eq_zero_of_P0   : P₀ = 0 → ∀ z, oddCircleEq (k+2) v z = 0        -- true for EVERY z
```

So the "kernel line" I named in the brief does not exist: the kernel vector cannot carry a line at `P₀ = 0`.
The `−conj(v_{m+1}) z − v_{m+1}\bar z + …` equation I wrote is **not** what `oddCircleEq` reduces to. The prefix
already had the correct negative statement at `n = 5` (`oddCircleEq_five_degenerate`): the real line is
`k0 − z k1 − z̄ k2`, and `k0` is **not** a coordinate of the kernel vector.

**Target B as I stated it is false**, and this is proved in Lean (`p0_children_gcircleS_false`), not just claimed:
`dX = (−1, −½+½i, −⅕+⅖i, −½−½i, 1+2i)` has all centres nonzero and `P₀ = 0`; its first four centres are the
inversions of four tangent lines of one parabola, so that child has `mD = 0` and its level point is `x/0 = 0` under
Lean's division convention. The child points `−⅕+⅖i, −7/15+⅗i, −1+i, 0` have `cD = 2/45 ≠ 0`, so no generalized
circle passes through them. **`∀ j, d j ≠ 0` is too weak; general position (or an explicit `hPi`) is what carries
the statement** — the same lesson as r9/r10, now a Lean counterexample rather than a remark.

**Target B, corrected, is a real gain:**

```lean
hodd_five : ∀ d : Fin 5 → ℂ, GenPosN d →
  ∃ Y, IsGCircleS Y ∧ ∀ i : Fin 5, ↑(levelPointN 4 (crossVec (KP 4 (d ∘ i.succAbove) c̄))) ∈ Y
p0_children_gcircleS_genPos : GenPosN d → P₀ = 0 → (same conclusion)
```

proved by a **route that does not use the kernel circle at all**: `levelPt_child_five` identifies each child level
point with the Miquel point of the subfamily, and then `Clifford.clifford_two_clean h.pos5` +
`Clifford.exists_gcircleS` gives one generalized circle through all five. So **`hodd` at `k = 0` is now
unconditional in `P₀`** — the `hP0` hypothesis of `hodd_levelPoint` is not needed at the base case.
