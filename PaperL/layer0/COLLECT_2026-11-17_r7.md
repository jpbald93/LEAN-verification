## 3. What landed

**Target A — the parity identity (general `m`, symbolic `i`, `[CommRing R]`).** The brief expected
"drop row `i` and column `q`"; the truth is different and the job derived it, then checked it on `m = 1, 2`
by entry comparison:

```lean
theorem KP_sub_eq_odd (m : ℕ) (x y : Fin (2*m+3) → R) (i : Fin (2*m+3)) :
    (subRowsOdd m x y i).submatrix id (Fin.last _).succAbove = subScaled m x y i
theorem subRowsOdd_succ :   -- parent column l+1 = −x · sub column l, except at P_{m+1}
theorem crossVec_subScaled : crossVec (subScaled m x y i) j = (∏ r, y (i.succAbove r)) ·
    crossVec (KP (2*m+2) (x∘i.succAbove) (y∘i.succAbove)) j
theorem cramerO_P0 / cramerO_Q0 / cramerO_QL   -- (∏y)- or (∏−x)-scaled coordinates of w
```

So the even-subfamily matrix is **not** an exact submatrix of the odd parent — the parent's degree is one
higher in every entry, and the correct statement carries the row scalars `y (i.succAbove r)`. Dropping the
last column (`Q_{m+1}`) gives `y·sub`, not `sub`.

**Target B — the odd row relation.** `rowRelOdd` from `cramer_three`, and

```lean
theorem stepOdd_cleared_gen :
  (-1)^m·(∏ r, y (i.succAbove r))·(v₀·Q₀(w) − Q₀(v)·P₀(w)) + Q_last(v)·C_L = 0
```

with `C_L = (−1)^(2m+1)·(−1)^(m+1)·crossVec (subScaledX …) ⟨m+1⟩` — the mirror of `stepEven_cleared_gen`.

**Target C — the step itself, no case split, no `det7`/`det8`.**
