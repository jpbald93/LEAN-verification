## 3. What landed — and the brief was wrong about the centre

**The correction.** The brief (and round 7 §5, and the `oddCircleEq` docstring as I had written it) said the
circle has centre `Q₀/P₀`. It is **`conj Q / conj P`**. From the definition,
`oddCircleEq = |P|²|z|² − P̄Qz − PQ̄z̄ + |Q|² − |L|² = |P̄z − Q̄|² − |L|²`, hence
`= |P|²·(dist(z, Q̄/P̄)² − (‖L‖/‖P‖)²)`. With `Q/P` the identity is false: my numerics reject it in
**2,000 of 2,000** trials. This is a prose-level fix for the paper too — any sentence saying "centre `Q/P`"
must become `Q̄/P̄`.

```lean
theorem kernelCircle_scalar (a b c z : ℂ) :
    conj a*a*z*conj z - conj a*b*z - a*conj b*conj z + b*conj b - c*conj c
      = ((‖conj a*z - conj b‖^2 - ‖c‖^2 : ℝ) : ℂ)

theorem kernelCircle_eq (m) (v) (z) :                       -- no hypothesis
    oddCircleEq m v z = ((‖conj (v 0)*z - conj (v ⟨m+1⟩)‖^2 - ‖v last‖^2 : ℝ) : ℂ)

theorem kernelCircle_eq_dist (m) (v) (hv0 : v 0 ≠ 0) (z) :
    oddCircleEq m v z = ((‖v 0‖^2 * (dist z (conj Q/conj (v 0))^2 - (‖L‖/‖v 0‖)^2) : ℝ) : ℂ)

theorem kernelCircle_zeroSet (m) (v) (hv0) :
    {z | oddCircleEq m v z = 0} = Metric.sphere (conj Q/conj (v 0)) (‖L‖/‖v 0‖)

theorem kernelCircle_isGCircleS (m) (v) (hv0) :             -- TARGET A
    Clifford.IsGCircleS (((↑) : ℂ → OnePoint ℂ) '' {z | oddCircleEq m v z = 0})
```

`kernelCircle_isGCircleS` takes the **sphere branch** of `IsGCircleS`, through `kernelCircle_zeroSet`. Both
`m` and `v` symbolic; no `fin_cases`.

## 5. What the assembly still needs — the three-piece list, corrected

The r7 three-piece list was right about the shape but **under-counted the hypothesis side** and, on reading
`cliffordChainS_all_of` again, was vague about what "the `hodd` payload" costs. Current state:

1. ~~`IsGCircleS` of the kernel circle~~ — **CLOSED this round** (`kernelCircle_isGCircleS`, no hypothesis
   beyond `v 0 ≠ 0`).
2. **The `E` identification.** `cliffordChainS_all_of` takes `E` as a *parameter*; `hodd_levelPoint` already
   writes the point as `levelPointN`. So what is left is to **instantiate `E`**: prove
   `E (2k+4) c = levelPointN (2k+4) (crossVec (KP (2k+4) c c̄))` against jack's `second`/`miquel`. Only
   `n = 4` exists (`levelPointN_four = miquel`). This is the next job.
3. **Bookkeeping — three hypothesis families, not two.** Both payloads need, per vector: `v 0 ≠ 0` (for the
   circle) **and** `v ⟨n/2⟩ ≠ 0` (the `levelPointN` denominator and `StepEven`/`StepOdd`'s own premise), plus
   the *determinant* conditions `hP0` / `hPi`. Concretely:
   - `hd : ∀ j, d j ≠ 0` is **free from `GenPosN`** — `Transversal c d := conj c * d ≠ c * conj d` is false
     whenever either argument is `0`, so any two distinct indices give both nonzero. A two-line lemma, not a
     research item.
   - `hP0` and `hPi` are **determinants** (`crossVec … 0`, `crossVec … ⟨k+2⟩`), not coordinates. `GenPosN`
     supplies `triP ≠ 0` and `cycP ≠ 0` on triples (`GenTriple`), so this is where the real work is: relate the
     parent's `P₀` and each subfamily's middle coordinate to `triP`/`cycP`.
   - These must hold at **both** levels the even payload uses (see 5b), so it is three index families.
4. **The even payload (`heven`) has no numbered-side theorem yet.** New finding this round: `heven` is
   *not* `StepEven` — `StepEven m` says the parent's level point lies on each subfamily's kernel circle
   (one circle per subfamily), while `heven` asks for **one** circle `Y` through `E (2k+6) c` and through all
   the level-`(2k+4)` points of the sub-subfamilies. Reading `cliffordChainS_all_of` (lines 330–364), that `Y`
   is exactly the kernel circle of the `(2k+5)`-subfamily: `StepEven` puts the parent's level point on it and
   `StepOdd` puts the `(2k+4)` points on it. So **no new geometry is needed** — but the statement has not been
   written, and it needs both step lemmas plus Target A plus the same bookkeeping at two levels. It is a
   `hodd_levelPoint`-shaped job, one level up.

So the honest remaining work is: **(2) `E` identification**, **(3) `GenPosN` → `hP0`/`hPi` bookkeeping**,
**(4) `heven_levelPoint`**. Then `cliffordChainS_all_of` is instantiated and C5 moves off REDUCED.
