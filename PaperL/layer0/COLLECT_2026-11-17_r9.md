## 5. The finding that matters: **`GenPosN` does not imply `P₀ ≠ 0`**

Both `hodd_levelPoint` and `heven_levelPoint` carry `P₀ ≠ 0` (the parent's / subfamily's `P₀` cross-vector
coordinate), because `kernelCircle_isGCircleS` only covers the sphere branch. The open hope was that `GenPosN`
supplies it. **It does not.**

I searched for a configuration with `GenPosN` and `P₀ = 0`, and then made it exact:

```python
c = [ -203/100 + 609/400 i,  -1659/676 + 2765/2704 i,  -2667/1156 + 1778/1445 i,
      -6483/2500 + 15127/20000 i,  -6051/3364 + 10085/5887 i ]        # n = 5, all Gaussian rational
```

For these five points, in exact rational arithmetic (`p0_counterexample_exact.py`):

| quantity | value |
|---|---|
| `crossVec (KP 5 c c̄) 0` | **exactly `0`** |
| all 10 `Transversal` values | min modulus **1.321** |
| all 10 `triP` values (`GenTriple`) | min modulus **0.0205** |
| all 10 `cycP` values (`GenTriple`) | min modulus **0.0776** |

So `GenPosN c` holds and `P₀ = 0` — the degenerate case is a **codimension-1 family inside general position**, not
a boundary case. `P₀` is the coefficient of `z z̄` in `oddCircleEq`, i.e. exactly "the kernel is a circle, not a
line"; the construction places the five centres on a radial cubic `βz²z̄ − α z z̄² − γ z̄² + δ z z̄ − ε z² = 0`,
which is a curve of vanishing `P₀`.

**And the geometry is still fine — it is a line.** Taking the float twin of that configuration and computing the
five subfamily level points (`p0_levelpts_collinear.py`): they are collinear with residual **9.8e-12** to the best
line, against **1.6e-4** for a 0.1 % perturbation of the same configuration (control). So when `P₀ = 0` the level
points lie on a *line*, which is a generalized circle by the **second** branch of `IsGCircleS`.

Consequences, in order of importance:

1. `hP0` is **not** a lemma anyone can prove — the route "get `P₀ ≠ 0` from `GenPosN`" is closed, so the assembly
   cannot be finished with the sphere branch alone. `hodd_levelPoint` and `heven_levelPoint` are true statements
   but they are not yet the payload `cliffordChainS_all_of` needs.
2. The fix is the degenerate branch: `P₀ = 0 ⟹ the level points are collinear ⟹ IsGCircleS` via the line branch.
   The numeric evidence for the collinearity is clean, and the object to formalise is the *limit* of the kernel
   circle as `P → 0` (the linear part of `oddCircleEq`), not `oddCircleEq` itself — whose zero set is vacuous
   (`|Q|² = |L|²`, independent of `z`) exactly in this case.
3. `Ept` and the `n = 4` case are unaffected (Target A derives its premise from `mD ≠ 0` through `GenPos4`, and at
   `n = 4` the coordinate *is* `mD`).
